# Agent 权限矩阵与同步规则

## 权限矩阵（读 / 写 / 禁）

| Agent | 读 | 写 | 禁止写 |
|---|---|---|---|
| 总台-Router | 全仓库 | 不写仓库（状态存数据库） | 整个仓库 |
| KnowledgeWorker | 全仓库 | `00-Inbox` `10-Knowledge` `20-Skills` `30-Reviews` | `40-Agents` `90-System` |
| CodeWorker | 全仓库 + 代码仓库 | `60-Outputs` `50-Events`(追加) | `10-Knowledge` `40-Agents` `90-System` |
| ChatWorker | `10-Knowledge` `20-Skills` `30-Reviews` | `00-Inbox` `60-Outputs` | `10-Knowledge` `40-Agents` `90-System` |
| Grok bot | 全仓库 | `00-Inbox` `60-Outputs` | `40-Agents` `90-System` |
| Mausbot | 全仓库 | `00-Inbox` `60-Outputs` | `40-Agents` `90-System` |

原则：**写权限最小化**。知识沉淀（`10-Knowledge`）只有一个写入口——KnowledgeWorker，避免多人改同一篇正式笔记。

## 同步规则（每个 Agent 必守）

1. **写前先拉，写后即推**：统一走 `bash 90-System/sync/sync.sh`
2. **署名提交**：同步前设 `AGENT_NAME`（router / knowledge / code / chat / grok / maus），commit 信息带前缀（`kb:` `code:` `chat:` `grok:` `maus:`），谁写的一眼可审计
3. **分区写入**：文件名一律 `YYYY-MM-DD-主题-署名.md`，只新增/追加，不覆盖他人文件
4. **成果即回写**：任务完成 = 成果已 push 到云端；未 push 的任务视为未完成，Router 必须催办
5. **配置改动走人工 PR**：`40-Agents/`、`90-System/` 任何 Agent 不得自动改，需 大古老师 审批合并

## 冲突隔离设计

- 每个 Agent 的写入目录交集最小（唯一交集 `00-Inbox`、`60-Outputs`，且靠文件名署名天然隔离）
- `50-Events/` 只追加不修改
- sync.sh 使用 `pull --rebase --autostash`，残余冲突时保留双方内容按追加合并，禁止 `--force`
