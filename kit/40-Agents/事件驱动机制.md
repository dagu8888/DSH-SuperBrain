# 事件驱动机制：快过滤 → 慢判断 → 直通

## 流水线

```
事件源（群消息 / PR / CI / 邮件 / 知识库变更）
   │
   ▼ Gateway 标准化为 Event{source, thread_id, sender, type, payload}
   │
   ▼ ① 留痕：append 50-Events/YYYY-MM-DD.jsonl（全部事件，含被丢弃的）
   │
   ▼ ② 快过滤（filters.yaml，纯规则，预算 <50ms，不调模型）
   ├── DROP   → 结束
   ├── URGENT → 跳过③④直接派单 + 立即回执用户"已加急处理"
   └── ALLOW  ↓
   ▼ ③ 直通快路径：查路由表 routing_table[thread_id]
   ├── 命中且未过期且未换话题 → 直接转发给该 Worker（不调模型）
   └── 未命中 ↓
   ▼ ④ 慢判断（Router 轻量模型，预算 <2s）
       输入：事件摘要 + dispatch_table 意图列表
       输出：{intent, worker, confidence}
       confidence < 0.6 → 回问用户一句澄清；仍不明 → default: chat-worker
       → 写入路由表 → 派单
```

## 直通机制（同一话题不换人）

路由表存**数据库**（重启不丢），结构：

| thread_id | worker_id | last_active_at | 状态 |
|---|---|---|---|
| 群A-话题123 | chat-worker | 2026-11-08 14:00 | active |

规则：

1. **命中直通**：thread_id 有记录 → 后续消息跳过慢判断，直达同一 Worker 的会话上下文
2. **过期**：私聊 30 分钟、群聊 60 分钟无活动 → 记录失效，下条消息重新走慢判断
3. **换话题重派**：消息强匹配其他 Worker 的关键词（如 chat 话题里出现"评审一下这个 PR"）→ 重新慢判断并更新路由表
4. **失败重派**：Worker 报错或超时（默认 10 分钟无汇报）→ Router 重新派单并通知用户

## 异步与回执（不卡对话）

- Router 收到 ALLOW/URGENT 事件 → **立刻回执**"已收到，处理中"（<1s），任务进队列异步执行
- Worker 完成 → 强制回写知识库（commit & push）→ 向 Router 汇报 ≤100 词 → Router 统一回复
- 群聊只发结论 + 知识库路径；私聊/其他场景完整输出

## 典型场景走查

| 场景 | 快过滤 | 走向 |
|---|---|---|
| 群里有人灌水 | DROP | 仅留痕 |
| 群里 @机器人 问问题 | ALLOW | 查路由表→直通或慢判断→chat-worker |
| 群里说"线上挂了" | URGENT | 直接派单 + 回执 |
| 主分支 PR 提交 | URGENT | code-worker 评审→报告写 60-Outputs |
| CI 失败 | URGENT | code-worker 根因分析 |
| CI 成功 | DROP | 仅留痕 |
| Agent 改了 40-Agents/ | URGENT | 红色告警（配置只能人工 PR） |
| Inbox 新增文件 | ALLOW | knowledge-worker 整理 |

## 落地实现提示

- 快过滤引擎：一个 ~100 行的 Python 脚本即可，逐条匹配 filters.yaml 的 if 条件（regex / in / is / contains）
- URGENT 的 `dispatch` 字段可跳过慢判断直接指定 Worker
- `${IMPORTANT_CONTACTS}` 等敏感配置走环境变量，不进仓库
